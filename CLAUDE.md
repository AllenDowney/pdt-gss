# Working in pdt-gss

This repo holds GSS metadata built to the PublicDataToolkit standard. The standard is `../PublicDataToolkit/STANDARD.md`; read it before changing records.

- The records cover every variable of releases 7224r3 (6,942) and 7224r3a (6,943).
- `metadata/releases/`, `metadata/groups.jsonl`, `metadata/annotations/`, `metadata/derived/` and `build/report.md` are generated by `build/build_records.py`. Don't edit them; change the build, `build/releases.yaml` or `build/slice.yaml`.
- `metadata/links.jsonl` and `build/links_report.md` are generated by `build/build_links.py` from `build/release_notes_7224.yaml`, a hand transcription of NORC's release notes. Fix a link by fixing the transcription.
- `metadata/corrections.jsonl`, `dataset.yaml`, `sources.yaml`, `EXTENSIONS.md`, `build/releases.yaml`, `build/slice.yaml` and `build/release_notes_7224.yaml` are edited by hand.
- `build/slice.yaml` names the snake_case slice, a subset of 50 variables that PublicDataToolkit's eval keys refer to. It also holds hand-entered measures for them. The build writes the slice as the group `slice-snake-case`.
- `data/` is gitignored and never committed.
- Run `make build`, `make views`, then `make check` (use the CultureWar conda env, which has pandas, pyreadstat, PyYAML and jsonschema). The full build takes several minutes.
- `make build` first runs `make gssrdoc` and `make codebook`:
  - `make gssrdoc` fetches gssrdoc's `gss_doc.rda` at the commit pinned in `sources.yaml` and converts it with `build/convert_gssrdoc.R`. That needs an Rscript with jsonlite (`RSCRIPT=~/miniforge3/envs/pdt-xlang/bin/Rscript`).
  - `make codebook` runs pdftotext on NORC's 2024 codebook.
- Every release is built from gssrdoc 0.9, which documents Release 3. The 7224r3a records say so in `provenance.record.note`. The two names gssrdoc lacks (`vote_ts`, `pres_ts`) come from the Stata file and the codebook.
